# 班级座位助手

教师登录后管理班级座位。数据保存在 Supabase，同一账号的电脑和手机会同步。班会可以投屏选座：积分高的小组先选一片连在一起的座位，组内积分高的同学先选座。课堂展示链接只显示座位、小组和积分。

## 启动

需要 Node.js 22。项目根目录提供 `.nvmrc`。复制 `.env.example` 为 `.env.local`，填入 Supabase 项目地址和 publishable key。

```bash
npm ci
npm run dev
```

打开终端显示的地址，通常是 [http://localhost:5173](http://localhost:5173)。在 WSL 或已安装 nvm 的 Linux 环境，也可以运行 `./start.sh`；脚本会尝试切换到 Node 22，并在首次运行时安装依赖。

首次打开会进入设置向导。可以创建班级并导入名单，也可以先用示例班级体验。后续数据会自动保存在当前浏览器中。

## Cloudflare Workers 自动部署

这是 Vite 静态前端，Supabase 配置在 `npm run build` 时写入浏览器脚本。Cloudflare 提示“不能将变量添加到只有静态资产的 Worker”时，应在 **Workers & Pages → class-seating → Settings → Build → Build variables and secrets** 中设置构建变量，而不是在运行时的 **Variables & Secrets** 中设置。添加以下两个变量，值从 Supabase 项目的 **Connect** 面板获取：

```text
VITE_SUPABASE_URL=https://你的项目.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_你的密钥
```

构建命令设为 `npm run build`，部署命令设为 `npx wrangler deploy`，根目录使用仓库根目录。保存变量后重新运行构建并部署；已生成的静态文件不会因为修改变量而自动更新。本地开发继续使用被 Git 忽略的 `.env.local`。这里只能使用 Supabase 的 **publishable key**，不要填写 secret key 或 `service_role` key。浏览器会看到 publishable key，因此 Supabase 数据表仍须配置合适的 RLS 策略。

## 图片加载优化

页面使用 `ui/webp/` 中的优化图片：学生头像为 128×128，座位图为 384×384，教室底图保留 1254×1254，侧栏插画为 640×853。原始 PNG 保留在 `ui/png/` 和 `ui/assert/`，更换素材时请先按显示尺寸导出 WebP，避免重新引用大图。

图片通过 Vite 导入，构建后生成带内容指纹的 `/assets/` 地址。`public/_headers` 会复制到 `dist/_headers`，让 Cloudflare 为这些资源设置 `Cache-Control: public, max-age=31536000, immutable`；素材变化会产生新地址。HTML 继续使用 Cloudflare 默认的重新验证策略，便于及时获取新版本。登录页插画也使用指纹地址，并延迟加载，手机布局隐藏插画时无需下载。

修改后需要重新构建、部署才会在线上生效。可在浏览器开发者工具的 Network 中确认图片为 WebP、响应包含上述缓存头，重复访问时使用浏览器缓存。检查缓存时不要勾选 Disable cache。

## 使用流程

### 1. 建立班级和教室

- 在“学生与规则”中添加姓名，或从 `.xlsx`、`.csv` 导入。表格中的“姓名”“性别”列会自动识别；也可以在学生详情中补充性别、眼镜标识和教师备注。
- 点击“编辑教室”，按排增减桌子、切换单人桌和双人桌，或批量给每排添加桌子。点击座位可停用或启用，门窗位置也可调整。
- 在“教室”页面的“讲台两侧 · 值日”中，可分别添加左、右特殊座位并指定学生。特殊座位也可手动换座，自动排座和小组选座会保留值日；移除后原学生回到待安排，历史版本、投影和打印会保存并显示这些位置。
- 停用已有学生的座位后，该学生会进入左侧“待安排”名单。可以把姓名拖到空位，或先点姓名再点空位。

### 2. 排座和微调

- 点击首页“帮我排”，选择“尽量少动”“轮换位置”“换换同桌”等目标，核对规则并比较方案。采用方案后仍是工作草稿，可以继续修改。
- 点击座位选中学生，再用右侧“换座”选择目标座位；也可以直接把座位拖到另一座位。两名学生交换时会显示移动动效。锁定的学生需要先解锁。
- 名单中的待安排学生拖动时显示简洁的姓名预览。首页座位图可缩放，“适应”按钮恢复默认大小。
- 在“学生与规则”中设置座位需求和学生关系。必要规则、尽量满足的规则与锁定位置会在生成方案时参与计算。

### 3. 发布和回看

- “发布座位”会检查人数和必要规则。填写开始使用日期、学期周次与备注后，可以立即启用，也可以保存为待启用版本。
- “历史版本”可将两个版本或工作草稿并排对照，把旧版复制回草稿，或删除单条版本记录。删除记录可以撤销；删除当前正式版的**记录**不会取消正在使用的正式座位。
- “座位轮换”可按学生、轮次和日期查看轨迹。投影视图用于带领学生换座，也可以打印教师版或学生版座位表。打印支持 A4 横向与 PDF 保存，可先预览，再切换教师/学生视角；学生版突出姓名，教师版附规则备注。

## 快捷操作

| 操作 | 快捷键 |
| --- | --- |
| 撤销 | `Ctrl/Cmd + Z` |
| 重做 | `Ctrl/Cmd + Shift + Z` |
| 搜索学生 | `/` |
| 锁定或解锁选中学生 | `L` |
| 取消选择 | `Esc` |

在座位图中按住 `Ctrl/Cmd` 或 `Shift` 点击，可多选学生。

## 数据与备份

班级、小组、学生和积分保存在 Supabase。课堂展示地址可以投到另一块屏幕，观众不能修改。教师 PIN 只用于课堂屏上的加减分、重选区域和退出，教师可以在「小组与积分」里自己修改。

## 验证与构建

```bash
npm test
npm run build
```

测试覆盖锁定、必要规则、容量、手工移动、轮换和混合桌型。项目使用 React、TypeScript 和 Vite，排座计算在浏览器本机运行。
